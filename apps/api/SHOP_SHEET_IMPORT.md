# 教師與組織預購表單同步

入口：商品設定 →「組織預購同步」（`/shop/admin?view=imports`），限 `shop:manage`。
來源預設停用；可以先「同步一次」核對結果，再啟用每分鐘自動同步。
**同步一次會建立訂單並排入成立通知信，不是預覽。**

## 啟用前的環境設定

來源若原本已允許連結讀取，可在 `config.public_sheet_id` 指定已核對的分頁 `gid`，
以匿名唯讀 CSV 匯出讀取，不需要 Google 服務帳號。此設定不會變更來源分享權限；
分頁 ID 可從網址的 `gid` 或 Google Sheets metadata 取得，不可用工作表順序猜測。
CSV 保留同欄數字與尺寸文字，最多 100 個資料欄、10,000 列、8 MiB；超限整次停止。
Google 匯出重新導向只接受 Google 文件及匯出內容主機，不會帶入任何認證。

未設定 `public_sheet_id` 的私人試算表沿用以下唯讀認證：

1. 在核准的部署流程套用 Alembic migration `20261109220000`。
2. 啟用 Google Sheets API，讓專用 Google 服務帳號以「檢視者」權限讀取來源試算表。
3. API 與 default queue worker 均須具有 Application Default Credentials。
   可將服務帳號檔案以唯讀 secret 掛載，並設定 `GOOGLE_APPLICATION_CREDENTIALS` 為掛載路徑。
   不把金鑰寫入原始碼、設定畫面或試算表；不需要讓表單公開。
4. 確認 Celery Beat、default worker、outbox 與 email worker 正常運作。
   同步排程是 `api.services.shop_tasks.sync_organization_preorders`，每 60 秒執行。
5. 後台新增來源、選擇系統內對應商品主題，確認欄名後同步一次。
   試算表名稱可自訂；工作表分頁名稱必須完全一致。

對話中的 Google Drive 連線不會自動成為正式系統的長期讀取憑證。
本功能只讀試算表，不會修改 Google 表單、回覆或分享權限。

## 欄位與判讀

預設欄名為「時間戳記」「電子郵件地址」「姓名」「辦公室」；「職稱」不當作商品。
如有「若所屬辦公室未在上列選項」且有填答，使用其內容作為辦公室／組織。
欄位依名稱對應，可以調整順序。不同表單可在後台設定欄名及忽略欄位。

商品名稱比對只去掉標價、空白與括號，限所選商品主題；有重名或別名時由管理者
設定「試算表商品欄名 → 系統商品」。例如「帽踢」與「帽T」需明確對應。
價格與變體加價一律取自系統商品，不從表單標題推算，不自動建立商品或變體。

已確認只計數量的商品，可在 `config.quantity_only_options` 設定「商品 ID → 預設選項 ID」。
例如此批復刻款背包固定選擇「不加購」吊飾，接受 `2`、`２個`、`兩個` 等數量；
不採用標題誤植的尺寸。此設定只影響該匯入來源，預設選項必須屬於該商品、啟用且加價為 0。
選項失效或變成加價時，整列轉待確認；尺寸或加購文字不會被強制換成預設選項。

支援單一規格群組（尺寸、鞋碼等）的多規格填答，例如：

| 填答 | 判讀 |
| --- | --- |
| `L 2件、XL×1` | L 兩件、XL 一件 |
| `Ｌ：２件；ＸＬ＊１` | L 兩件、XL 一件 |
| `XXL一件`／`2XL` | 商品存在 2XL 時對應該規格；單填尺寸視為一件 |
| `大號兩件，中號一件` | 商品有 L／M 時對應 L 兩件、M 一件 |
| `S/M/L各一件` | 三個尺寸各一件 |
| `L(2件)、XL（一件）` | L 兩件、XL 一件 |
| `42碼兩雙` | 商品有 42 碼時對應兩雙 |
| `兩把`／`２個` | 無規格商品兩件 |
| `XL買1件`／`買XL1件` | XL 一件 |
| `買1件`／`購買兩把` | 無規格商品一件／兩件 |

不明尺寸、帶小數或負數、只填數量但缺尺寸、總數不一致、額外自由說明、
多組規格組合、限購／身分限制／劃位商品、缺姓名／Email／辦公室、庫存不足均列待確認。
不會只匯入一列中可辨識的部分，也不會保留失敗列的扣庫存、應收或通知。
每個規格合計為 1–100 件，沿用既有單項數量範圍。

## 既有訂單流程

每筆回覆建立獨立的 `sheet_import` 訂單，不替填答者建立登入帳號，也不依 Email
自動取得既有帳號的訂單存取權。訂單保存姓名及辦公室快照；`class_id` 保持空值，
不建立虛構班級、不交由學生班代收款。訂單列表的班級／處室顯示辦公室。
報表、品項數量與收據使用同一批訂單資料。

訂單狀態為已成立、**尚未付款**（`confirmed`、`cash_on_pickup`、`is_paid=false`），
建立未收款的應收款。按系統商品價格計算，套用與一般訂單相同的適用自動優惠，
包含套組、滿額與主題優惠；不猜測優惠碼，不依填答 Email 取得帳號／學號限定優惠。
使用次數、有效期間、商品／主題與數量門檻沿用既有規則；優惠異動也會重算未收款預購。
成立通知以「您好」稱呼訂購人，列出商品、尺寸、數量與金額，明示交貨時付款、
目前無須預繳或匯款及交貨安排將另行通知。更正商品、尺寸、數量或資料時，
使用 Google 表單的「編輯回覆」修改原回覆後重新提交，無須另填新表單。
成功修改後寄送「預購訂單更新通知」，列出最新明細、優惠及應付金額，保留原訂單編號。
已收款、已截止或未收到更新通知時，可依公開聯絡頁提供訂單編號洽詢班聯會；
不需登入學生帳號，信中不放入需要登入帳號的訂單連結。
訂單、扣庫存、應收、匯入帳本與 outbox 在同一交易保存，commit 後才處理通知。
交貨後由既有訂單管理確認收款；不列入學生催繳收件人。

## 去重、修正與故障排查

- 使用固定的回覆識別欄位去重；預設時間戳記。排序、插列或重跑不重複建單。
  時間戳記相同的回覆全部列待確認；有碰撞時應在建立來源前準備唯一且固定的回覆 ID 欄位。
  已建立來源不能變更試算表、分頁或識別欄名。若表單編輯更新了時間戳記，僅在
  收集 Email 可唯一對應消失的舊回覆時延續原帳本；同信箱多筆回覆、Email 同時變更、
  或原列換成其他人等無法唯一對應的情況保留待核對，不重複建單。
- 待確認列可修正原回覆後重新同步；已成立且未收款的訂單若填答內容不同，
  在同一交易更新原訂單、依新舊件數差額調整庫存、重算優惠次數及應收，並排入更新通知。
  尺寸不明、庫存不足、截止或已收款／取消／退款時保留原訂單及完整原交易，列待核對。
  清空所有商品不視為取消指示，需洽班聯會取消。後台同步結果分列新增、更新、略過及待確認筆數。
- 未修改的既有未收款預購也會補算／重新核對自動優惠；金額改變時寄送更新通知，
  不重新建立品項或扣庫存。一般重跑不重複增加優惠次數或通知。
- 取消或清除系統訂單後仍保留匯入帳本；重抓原回覆不會使訂單復活。
- 無法讀取的來源會顯示最近錯誤；核對服務帳號、唯讀分享、API 啟用及精確分頁名稱。
  單一工作表上限 100 欄、10,000 列（含空白格與標題）；超限會拒絕同步，不靜默截斷。
- 後台分頁列出列號、原因與已建訂單連結，不在匯入帳本另存原始姓名或 Email。
  outbox 保留寄信所需的收件人與明細，沿用既有通知保存／重試機制。
- SMTP／佇列失敗沿用 outbox 與 mail worker 重試；通知遞送具既有 at-least-once 限制，
  worker 在寄信邊界崩潰時仍可能重送。一般重新同步不會新增第二個通知事件。

Google API 與認證介面依 [Sheets values.get](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get)
與 [google-auth](https://google-auth.readthedocs.io/en/latest/user-guide.html) 文件。
Migration downgrade 遇到沒有帳號的外部訂單會中止，避免為了退版刪訂單或偽造帳號。
