# Google Drive 資料來源

法規與活動照片使用後端 `GOOGLE_DRIVE_API_KEY` 讀取「知道連結即可讀取」的資料夾。
API 金鑰只存放於伺服器，不加入前端設定。需在 Google Cloud 啟用 Drive API；
資料夾及檔案都必須允許公開讀取。此功能不使用維護者的 Google Drive 插件登入狀態。

## 管理入口

- 法規查詢 → 資料同步 → 法規來源同步：選擇組織，每行填一個資料夾網址或 ID，
  最多 20 個；沿用每日／每週／手動排程及該組織的 `regulation:admin` 權限。
- 活動影像管理 `/admin/gallery` → Google Drive 同步：先發布活動，再新增來源。
  每個來源選擇活動，可指定活動環節、預設攝影師及是否遞迴子資料夾。
  可將多個來源放入同一活動，亦可對不同活動分別設定來源，最多 50 個來源。
- 同一處的「攝影師對應」設定電子郵件與公開姓名；設定及同步 API 要求
  `site:manage` 或 `admin:all`，公開網站只收到姓名，不會收到電子郵件對照。

照片排程可選每 15 分鐘、每日或僅手動；非手動設定儲存後會排入首次同步。
Celery Beat 每分鐘檢查已持久化的要求，worker 執行 `api.services.gallery_tasks.sync_gallery`。
部署時需套用 `20261115160000` migration，並重新啟動 API、worker 與 Beat。
本次開發不包含正式環境的 migration、服務重啟或部署。

## 署名與分類

公開 Drive API 沒有可靠的「原始上傳者電子郵件」。本系統以檔案 `owners.emailAddress`
對應攝影師，**不以最後修改者冒充上傳者**。擁有權移轉、代傳照片或 Google 未提供
電子郵件時，無法由公開 Drive 確認原始上傳者，請使用資料夾預設攝影師或人工署名。
多位擁有者對應到不同攝影師時也使用資料夾預設值。

直接指定子資料夾的設定優先於父資料夾的遞迴結果。來源未填環節時，使用相對於
來源根目錄的子資料夾路徑。公開活動頁可依攝影師及活動環節篩選。

參考：[Drive File 欄位定義](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)。

## 同步行為與限制

- 法規：所有來源完成列舉後才開始更新，以 Drive 檔案 ID 去重。任一來源列舉失敗
  會中止本輪，沿用既有版本比對、沿革與公布狀態檢查；檔案解析錯誤逐份回報。
- 照片：下載 JPEG／PNG／WebP，單檔最多 30 MB、4000 萬像素，縮至最長邊 2560px
  並轉 WebP，移除 EXIF／GPS 等 metadata。照片描述與替代文字欄位預設為空，
  公開圖片元件仍提供既有無障礙名稱。
- 同一活動內依 Drive 檔案 ID 去重，以 checksum 判斷影像更新；同一檔案可出現在
  不同活動。既有人工描述、精選設定與人工改過的署名／環節會保留。
- 人工從網站刪除的照片不會於下次同步自動復活；Drive 刪除或移走來源檔案也不會
  自動刪除網站照片。移除來源只停止後續匯入。
- 每個來源最多 100 個資料夾、1000 張照片，全部來源最多 2000 張。
  每次最多處理 50 張需下載的照片，剩餘項目續批處理，失敗項目不會擋住後面的照片。
- 照片來源部分失敗時仍保留其他來源的成功結果，報告列出錯誤；只有完整批次成功
  才更新「最近成功同步」。任務執行前重新檢查設定者是否仍具網站管理權限。
- 來源設定及同步任務共用資料列鎖；照片下載完成後再鎖定並讀取最新公開設定合併。
  後台編輯中的舊相簿快照仍由既有 fingerprint 衝突提示保護。

真實 Drive API 連線尚需使用部署環境的金鑰與實際公開資料夾驗收；本機回歸以
HTTP transport／外部 Drive 回應替身配合真實 PostgreSQL 驗證，未讀取個人雲端硬碟。
