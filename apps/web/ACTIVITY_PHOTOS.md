# 活動成果與影像紀事

公開入口為 `/gallery`，單一活動為 `/gallery/<活動識別>`；舊 `/activities` 永久轉址到 `/gallery`。
首頁主視覺使用第一個有照片活動的精選實照，未標記精選時使用首張照片，直接連到該活動。

## 管理方式

由公開網站工作台的「活動影像」進入 `/admin/gallery`，沿用 `site:manage`／`admin:all` 權限。

- 新增活動，填寫活動名稱、統一日期、短文與原始相簿連結。
- 批次上傳照片；勾選照片後可一次套用攝影師，或設為活動預設攝影師。個別照片署名優先於活動預設。
- 照片可排序、編輯說明及標記精選。精選最多八張進入編輯選輯；未標記精選時使用前八張，其他照片可由照片總覽或完整活動相簿瀏覽。
- 每個活動可獨立上傳主視覺及其署名。海報以完整比例放在活動內容的「活動主視覺」區，不裁成照片縮圖。活動開場優先使用實照，只有海報時才以海報開場。
- 可選開闊、交錯、橫向膠卷三種編排；開闊採主照全寬與次照雙欄，交錯只調整段落位置，不旋轉圖片。活動排序也決定首頁的主圖來源。
- 按「發布變更」才更新網站內容。失敗上傳可單獨重試，不重複加入成功的照片。
- 移除照片／活動是移除網站上的紀錄，不會刪除原始相簿或儲存服務中的檔案。

儲存前重新讀取現行設定，保留其他首頁內容；若另一位編輯者已更動活動資料，會阻止覆寫並要求重新載入。
上傳沿用網站現有的公開圖片服務，並非私密檔案儲存。

## 展示與互動

- 首頁與 Gallery 共享深墨底、字級與內容寬度。編輯選輯以大幅實照開場，日期、活動名稱與署名集中於圖片附近；移除浮動、旋轉與視差。
- 支援全部活動或單一活動的混合選輯；指定篩選保留於網址的 `event` 參數。
- 照片總覽使用平直網格，保留每張照片原始比例，包含正式海報；手機改為兩欄，編輯選輯改為單欄。減少動態偏好會停用全螢幕展開／收合動畫。
- 點選照片進入原生 dialog 全螢幕檢視，支援原位置展開、方向鍵、滑動切換、Escape、下載及分享。
- 編輯選輯尚有未展示照片時，活動頁才顯示一次「瀏覽全部照片」；照片總覽與完整相簿每次呈現 36 張，不在首次載入時下載所有原圖。
- 下載的是網站用圖片。分享網址指向特定活動及照片；下架聯絡導向既有聯絡頁。

## 資料與儲存

資料型別、容錯讀取與初始素材在 `src/lib/public-activity-albums.ts`。
活動存於既有 `PublicSiteSettings.homepage_blocks.activity_gallery`，格式為 `{version: 1, events: [...]}`，
透過原有 `/site/admin/settings` PATCH 儲存，沿用 FastAPI、PostgreSQL、稽核與圖片儲存服務。
本次未新增 DB 欄位或更動 API 契約，因此不需 migration。

未設定活動資料時使用使用者提供的迎新相簿精選；已儲存的空陣列表示清空，不重新出現預設素材。
讀取時驗證識別碼、日期、圖片網址與尺寸；不把活動日期猜成上傳日期，也不替未知攝影師署名。
公開資料更新沿用網站現有快取週期。

瀏覽器將新上傳圖片轉為最長邊 2560px 的 WebP 並去除 EXIF，再交給既有圖片上傳端點；Next.js Image 提供響應式顯示。
目前不自動同步 Drive。預設精選來自使用者提供的迎新活動資料夾，原始檔為 DSCF6280.jpg、DSCF6491.jpg、DSCF6554.jpg，
對應 `public/images/activities/welcome/` 的三張 WebP，合計約 311 KiB。

## 圖片失敗處理

`ActivityImage` 對已轉為 WebP 的公開上傳圖片直接讀取原圖，避免 standalone 圖片最佳化讀取同源 API rewrite 時回傳 500。靜態照片仍使用 Next.js 響應式最佳化；失敗時重試原圖。首頁／Gallery 開場會再嘗試同活動其他照片；全部失敗改為緊湊文字狀態，不保留大型空白圖片容器。全螢幕檢視沿用相同圖片載入策略。
